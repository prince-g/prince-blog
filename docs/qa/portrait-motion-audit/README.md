## Confirmed ghosting in the previous player

`ghost-2.5.jpg` shows several offset head/eye/mouth outlines at once. The original
portrait frames do not contain this layering. In the previous two-video implementation,
two video elements fade simultaneously for 180 ms over a permanently visible
front-facing poster. During the fade, all three poses can contribute pixels.
The player also holds its busy flag for the fade duration, limiting pose updates
to at most about 5.6 per second before seek latency. This accounts for both the
double-image appearance and low responsiveness.

The current player has removed these overlapping videos and opacity fades; this
section explains the recorded defect, not the current presentation mechanism.

`ghost-contact.jpg` is sampled every 0.5 seconds; `source-contact.jpg` every
0.25 seconds. Frames run left-to-right, then top-to-bottom.

## Source direction path

Times are approximate boundaries, based on visual inspection of the original
source, including the denser `up-boundary.jpg` and `down-boundary.jpg` sheets.

| Time | Existing motion |
| --- | --- |
| 0.0–0.4 | Initial front pose |
| 0.4–1.4 | Front to screen-right |
| 1.4–2.2 | Right-facing pose |
| 2.2–3.0 | Right to up |
| 3.0–3.9 | Up to left |
| 3.9–4.9 | Left-facing pose |
| 4.9–5.8 | Left to down |
| 5.8–7.0 | Downward pose |
| 7.0–8.1 | Down to front |
| 8.1–10.0 | Returned front pose |

The recording provides a continuous one-dimensional path, not an independent
two-axis head model. The current implementation uses a hidden video decoder and
one opaque 1280 × 720 canvas, retains the last decoded image while waiting, and
allows only one in-flight seek. Pointer movement updates a damped target time;
the next decoded frame replaces the canvas image without the former 180 ms
opacity lock. Native forward playback handles the initial presentation.

`gaze-mapping.ts` uses an 8.4-second circular timeline and takes its shorter
direction. The lower-right sector now includes the down-to-front and
front-to-right portions of the recording. The circular endpoint handoff has the
small visual mismatch noted below. Browser presentation rate still depends on
decoding and seeking; the 60 fps asset alone is not evidence of 60 fps rendering.

## Resting seam

`first-8.4-last.jpg` compares the initial frame, approximately 8.4 seconds, and
the final frame. The overall face and expression match, but hair, eyes, and
registration differ slightly. The grayscale mean absolute difference from the
initial frame is 4.35/255 at 8.383 seconds and 4.09/255 at 10.0 seconds. These are
usable front-facing resting poses, but not a proven invisible loop seam. The
current player treats 8.4 and zero as equivalent circular endpoints and targets
zero when leaving the hero. That permits a short return path, but may expose a
small registration change at the seam; it must not be described as pixel-perfect.

## Motion-interpolated output

New asset: `public/media/portrait/portrait-motion-60.mp4`.

- 1280 × 720, constant 60 fps, 599 frames, 9.9833 seconds.
- H.264, all 599 frames are I/keyframes, CRF 22, fast-start, no audio.
- 19,253,199 bytes (about 19.25 MB).
- Interpolation uses the original PTS with FFmpeg `minterpolate` motion
  compensation; it does not merely repeat frames.
- Original and prior web files remain unchanged.

`compare-2.2.jpg`, `compare-3.5.jpg`, `compare-5.0.jpg`, and `compare-7.0.jpg`
show source on the left and interpolated output on the right at the requested
motion checkpoints, cropped to the same 620 × 640 face region. Inspection found
no obvious duplicated pupils, torn mouth, or severely warped face at those
checkpoints. Fine hair, sticker lettering, and skin texture are softer in the
new compressed output. This spot check does not establish that every synthetic
frame is artifact-free; real browser motion remains part of acceptance.
